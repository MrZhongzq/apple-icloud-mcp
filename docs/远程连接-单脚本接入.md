# 远程连接：只带一个脚本接入

本文写给**另一个仓库**里的 Claude Routine。适用前提有两个：

- 它要通过远程 MCP 连接器用 iCloud；
- 它所在的环境里已经配好了自己的凭据。

你不需要 clone 本仓库，也不需要 `npm install` 或 build。只需要一个零依赖的脚本文件 `make-envelope.mjs`，外加一段写给模型的说明。

服务器怎么部署、访问密钥怎么发放，见 [`部署与-Routine-接入.md`](部署与-Routine-接入.md)。本文默认服务器主人已经给了你两样东西：

- 一把**访问密钥**，形如 `amk_…`；
- 服务器的**信封公钥**，形如 `amp1_…`。

---

## 一、它是怎么工作的

```
你的 Routine 沙盒                         claude.ai 后端                VPS 上的 MCP 服务器
──────────────────                       ────────────                 ──────────────────
环境变量 / .env（含 App 密码）
        │
node make-envelope.mjs  ──► 一行密文 ame1.…
        │                          │
        └── 模型把密文作为 apple_login 的 envelope 参数 ──► 连接器 ──► 用私钥解开、建会话
                                                                      连 iCloud、执行工具
```

- **连接器调用不是从沙盒发出的。** 发起调用的是 claude.ai 的后端，所以沙盒里的 `.env` 没法参与连接握手，凭据只能通过工具参数传过去。
- **对话记录里只会出现密文。** 明文密码只在两个地方出现过：你沙盒里的脚本进程，以及服务器的内存。
- **信封用完即作废。** 每个信封 5 分钟内有效，只能用一次，服务器一接受它就作废。所以**每次运行都要重新生成**，不能把上次的信封存下来复用。

## 二、一次性准备

### 1. 在 claude.ai 添加连接器

在设置 → 连接器 → 添加自定义连接器，地址填服务器主人给你的 `https://<域名>/mcp`。跳转到授权页后，输入你的**访问密钥**。然后在 Routine 的配置里挂上这个连接器。

### 2. 在 Routine 的环境里配置变量

可以设成环境变量，也可以写在仓库根目录的 `.env` 里。如果两边都写了，以环境变量为准。

| 变量 | 必填 | 说明 |
|---|---|---|
| `MCP_ENVELOPE_PUBKEY` | 是 | 服务器的信封公钥，就是 `amp1_…` 那一整行 |
| `ICLOUD_ACCOUNT_1` | 是 | Apple ID 邮箱 |
| `ICLOUD_APP_PASSWORD_1` | 是 | App 专用密码，在 appleid.apple.com 生成 |
| `ICLOUD_SENDER_1` | 视情况 | Apple ID 如果不是 `@icloud.com` / `@me.com` / `@mac.com` 地址，就必须填你的 iCloud 邮箱，否则邮件工具会被自动关闭 |
| `ICLOUD_LABEL_1` | 否 | 显示名 |
| `ALLOW_MAIL_READ_1` 等 8 个权限开关 | 否 | 读权限默认开、写权限默认关，规则和本仓库 README 里完全一样 |

几点注意：

- **只支持一个账号。** 信封里只装 `_1` 这一组变量；如果配置了 `ICLOUD_ACCOUNT_2`，脚本会拒绝运行。
- **`.env` 必须用 UTF-8 保存。** 用 Windows PowerShell 5.1 的 `>` 重定向写出的文件是 UTF-16，脚本读不出变量，会误报「缺少环境变量 ICLOUD_ACCOUNT_1」。
- **`.env` 不要提交进 git。** 在你的仓库里把它加进 `.gitignore`。

### 3. 把脚本放进你的 Routine

下面两种做法任选其一，**推荐 A**。

#### A. 把脚本提交进你的仓库（推荐）

只需要复制一个文件：本仓库的 [`scripts/make-envelope.mjs`](../scripts/make-envelope.mjs)。旁边的 `.d.mts` 是给本仓库测试做类型检查用的，不需要。放在哪都行，下面假设你放在 `tools/make-envelope.mjs`。

- **优点**：运行时不联网，版本固定在你自己的仓库里，别人改不了它。
- **缺点**：本仓库以后修了这个脚本，你要自己再复制一次。信封格式自带版本号（`ame1.`），只要服务端还认这个版本，旧脚本就能继续用；哪天服务端不认了，`apple_login` 会明确报错，不会悄悄出错。

复制时建议核对来源：从 GitHub 下载**固定提交**的版本，比对 sha256（见 B 里的哈希值）。

#### B. 每次运行时下载固定提交的版本

适合不想在自己仓库里放第三方文件的情况。**必须固定到某个提交，并校验哈希**：

```bash
curl -fsSL -o /tmp/make-envelope.mjs \
  https://raw.githubusercontent.com/MrZhongzq/apple-icloud-mcp/169d13469a63a9cfdfc5ccc8018ad76e6d8b800a/scripts/make-envelope.mjs
echo "3a83486b04393d5341e9f60bc7c9ae70fb799afa3737c9b2e76685e152c4b091  /tmp/make-envelope.mjs" | sha256sum -c -
```

- 第二行输出 `OK` 才能继续用。不是 `OK` 就停下，不要运行这个脚本。
- 这需要沙盒能访问 `raw.githubusercontent.com`。这一点在「受限」网络档位下**未实测**；如果下载失败，就改用做法 A。

**不要**直接从 `master` 下载，更不要用 `curl … | node` 管道运行：这个脚本经手的是你的 App 密码，从分支下载意味着谁能推送 master，谁就能改掉你每次运行的代码。

## 三、给模型的说明（粘贴进 Routine 的指令）

本仓库的 `SKILL.md` 是完整的工具契约。你可以把它一起复制进你的仓库；不复制也行，连接器自带的工具说明已经够用。但下面这几条规则必须写进 Routine 的指令里，路径按你实际放的位置改：

```
使用 iCloud 连接器时：
1. 先在仓库根目录运行 node tools/make-envelope.mjs。它的标准输出只有一行 ame1.… 的信封；
   把这一整行原样作为 apple_login 的 envelope 参数（不要传 account）。
   信封出现在命令输出里是正常的，但不要在回复里复述、引用或改动它。
2. 脚本退出码不是 0：把它 stderr 里那句原因报告出来，然后停止，不要自己去读或打印 .env / 环境变量排查。
3. apple_login 报「信封已过期」或「这个信封已经用过」：重新运行一次脚本、再登录一次——整个运行只重试这一次。
   报「信封是用另一把公钥加密的」或「信封无法解密」：不要重试，报告"需要向服务器主人要当前的公钥"。
4. 拿到 session_id 后正常调用工具；无论成功失败，最后都调用 work_done。
5. 不要打印 .env、env、任何 ICLOUD_* / ALLOW_* 变量的值。
```

脚本必须在 `apple_login` **之前紧接着**运行，不要在一次运行的开头生成、等到很久以后才用：信封只有 5 分钟有效期。

## 四、自检

在 Routine 里跑一次只读自检，提示词可以这样写：

```
用 iCloud 连接器做只读自检：按指令用信封登录，然后 mail_search 收件箱最近 3 封、calendar_list、reminders_lists，最后 work_done。不要做写操作。
```

如果只想先确认变量配齐了、暂时不登录，可以只检查脚本的退出码，让信封本身不出现在输出里：

```bash
node tools/make-envelope.mjs > /dev/null && echo "envelope config OK"
```

这条命令不会联网，也不会把任何信封交给服务器，所以不会作废任何东西。

## 五、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 脚本报「缺少环境变量 X」 | 变量没进到脚本里：环境变量没设，或者 `.env` 不在当前目录，或者 `.env` 不是 UTF-8 | 检查变量名和文件编码。需要指定文件时用 `node tools/make-envelope.mjs -- --env-file <路径>`；不加 `--` 的话，Node 24+ 会先自己处理 `--env-file`，文件不存在时直接以退出码 9 退出 |
| 脚本报「MCP_ENVELOPE_PUBKEY 格式不对」 | 公钥没贴完整，或者多了引号、空格 | 重新复制管理页上 `amp1_…` 那一整行 |
| 脚本报「配置了多个账号」 | 环境里有 `ICLOUD_ACCOUNT_2` 等变量 | 信封只装一个账号，去掉其余账号 |
| `apple_login` 报「这台服务器只接受加密信封登录」 | 模型没有传 `envelope` | 检查 Routine 指令第 1 条 |
| 报「信封已过期」 | 生成和使用间隔超过 5 分钟，或者沙盒时钟偏差超过 1 分钟 | 重新生成，紧接着登录 |
| 报「信封是用另一把公钥加密的」 | 服务器重建过密钥对，你的公钥旧了 | 向服务器主人要新公钥，更新 `MCP_ENVELOPE_PUBKEY` |
| 报 `AUTH_FAILED` | App 专用密码错误或已吊销 | 在 appleid.apple.com 重新生成，更新环境变量 |
| 邮件工具报权限被关 | Apple ID 不是 iCloud 邮箱、又没设 `ICLOUD_SENDER_1`；`apple_login` 返回的 `notices` 里会写明原因 | 设置 `ICLOUD_SENDER_1` 为你的 iCloud 邮箱 |
| 连接器报 401 / 要求重新授权 | 你的访问密钥被停用、被销毁，或者服务器升级后要求重新授权 | 联系服务器主人 |

## 六、安全须知

- **App 密码只在两个地方以明文出现**：你沙盒里的脚本进程，以及服务器在会话期间的内存。服务器磁盘上不存。用别人的服务器，就意味着你信任服务器主人。
- **截获的信封很难被利用**。截获者必须同时持有一把有效的访问密钥，而且要赶在信封 5 分钟有效期内、在你用掉它之前抢先使用。唯一的例外是服务器恰好在这 5 分钟内重启过：它会忘记哪些信封已经用过，于是同一个信封还能再被用一次。
- **服务器泄露了怎么办**：到 appleid.apple.com 吊销这个 App 专用密码，再生成一个新的。旧的对话记录里的信封，配合服务器私钥就能解开。
